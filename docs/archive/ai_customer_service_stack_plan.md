# 广西亿库光养硅藻环保科技有限公司 AI 客服技术栈初步规划

## 1. 项目目标
目标不是做一个“看起来很高级”的机器人，而是先把最耗人工、最重复的咨询自动化，减少客服和销售前置答疑的人力成本。

第一阶段建议聚焦：
- 自动回答高频问题
- 自动介绍公司和产品
- 自动收集客户联系方式
- 超出范围时转人工

## 2. 我对你说的 `flshGPT` 的理解
我先按 `FastGPT` 理解。

原因：
- FastGPT 很适合“知识库问答 + 可视化流程 + API 接入”场景
- 对中小企业来说，搭得快、维护相对轻、中文资料也更友好

如果你说的不是 `FastGPT`，后面我可以按你真实想用的平台重新调整。

## 3. 推荐技术栈

### 方案主线
`FastGPT + OpenAI/国产模型 + 向量检索 + 官网/微信接入 + 人工兜底`

### 3.1 平台层
推荐：`FastGPT`

负责什么：
- 搭建 AI 客服应用
- 导入 FAQ、产品资料、公司介绍、招商资料
- 配置知识库召回
- 编排对话流程
- 输出 API 给官网或微信使用

为什么推荐它：
- 上线速度快
- 不用一开始就自研后台
- 对“企业知识库客服”场景贴合

### 3.2 模型层
建议做成“主模型 + 备用模型”。

推荐搭配：
- 主模型：`GPT-5 mini` 或 `GPT-4.1 mini`
- 备用模型：后续根据成本和可用性切到国产模型

我的建议：
- 如果你更重视回答质量和复杂理解：优先 `GPT-5 mini`
- 如果你更重视成本：先用 `GPT-4.1 mini`

这样设计的好处：
- 以后不满意成本或速度时，可以只换模型，不用重做整套系统

### 3.3 检索层
推荐：
- 向量检索：使用 FastGPT 内置知识库能力
- Embedding：优先低成本模型，例如 `text-embedding-3-small`

它的作用：
- 把 FAQ、产品说明、施工说明等资料转成可检索的知识块
- 用户提问时，先找最相关内容，再让大模型组织答案

### 3.4 数据层
第一阶段建议准备 4 类知识库：
- 公司知识库
- 产品知识库
- 应用场景知识库
- 招商与合作知识库

你现在已有的是 FAQ 底稿，但还建议继续补：
- 产品参数表
- 施工/安装说明
- 常见对比问答
- 客户案例
- 联系方式与招商政策

### 3.5 渠道层
接入优先级建议：
1. 官网悬浮客服
2. 微信公众号或企业微信
3. 销售个人微信辅助问答

先做官网的原因：
- 最快看到效果
- 技术接入相对简单
- 最容易统计咨询量、转人工率、留资率

### 3.6 人工兜底层
一定要保留：
- 转人工按钮
- 留电话/微信表单
- 敏感问题不乱答
- 超出知识库范围时提示人工跟进

这是中小企业 AI 客服能否真正省人的关键。

不是所有问题都要 AI 自己扛，正确做法是把标准化问题自动化，把关键成交问题转给人。

## 4. 推荐系统结构

```text
访客提问
  -> 官网 / 微信入口
  -> FastGPT 应用
  -> 知识库检索
  -> 大模型生成回答
  -> 返回答案
  -> 如命中留资条件：收集手机号/微信
  -> 如超出范围：转人工
```

## 5. 第一阶段不要做太重
不建议一开始就上这些：
- 自研完整客服后台
- 复杂多 Agent
- 自动报价系统
- 语音外呼
- ERP / CRM 深度打通

原因很简单：
- 成本高
- 维护难
- 中小企业第一阶段很容易“还没省人，先多花钱”

## 6. 最小可行版本 MVP
我建议你第一版只做这些：

### 必做
- 导入现有 FAQ
- 补充公司介绍和产品卖点
- 设置回答边界
- 设置留资节点
- 设置转人工节点
- 接官网

### 可选
- 接微信公众号
- 给销售做一个内部问答助手

## 7. 推荐部署思路

### 更适合你当前阶段的方式
- FastGPT 自部署
- 模型 API 按量付费
- 先不自己训练模型

优点：
- 初期投入低
- 可边用边调
- 效果不好时容易调整

如果你现在要一个“适合中小企业、能较快上线、目标是降人工成本”的选择，我建议你这样定：

### 推荐组合
- 平台：`FastGPT`
- 主模型：`GPT-5 mini`

- 前端入口：官网客服窗口
